# Static site content release

Treat content as a small software change.

## Workflow

1. Confirm the audience, route, locale, title, description, canonical URL, and source evidence.
2. Follow the repository content schema and keep structured data separate from prose.
3. Add navigation, search metadata, RSS or sitemap entries, and related links when applicable.
4. Check images, alt text, loading behavior, external links, and mobile layout.
5. Run type checks, content checks, tests, a production build, and a clean diff review.
6. Preview the page in both available locales and record the deployed URL.
7. Update the change log or release note with what changed and what was verified.

## Output

Produce a content checklist, validation result, preview evidence, and concise release note.
